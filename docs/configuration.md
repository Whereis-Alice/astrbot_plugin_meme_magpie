# 配置说明

> [← 返回 README](../README.md) · [文档目录](README.md) · [English](en/configuration.md)

所有配置项都在 AstrBot 插件配置页里改，下面只列关键项。

## 收图

| 配置项 | 默认 | 说明 |
|:---|:---|:---|
| 开启表情包偷取功能 | `false` | 总开关 |
| 偷图模式 | `probability` | `probability` 按概率 / `cooldown` 按冷却时间 |
| 偷图概率 | `0.3` | 概率模式下每张图被收下的概率 |
| 偷图冷却时间（秒） | `30` | 冷却模式下两次收图的最小间隔 |
| 内容审核 | `false` | 开启后过滤不当图片，会多一次模型调用 |
| 审核异常时放行 | `false` | 审核调用本身失败时的兜底行为。默认拒绝（更安全），开启则放行 |
| 待审核池容量上限 | `200` | 待审核图片攒到上限就暂停收图，审核通过后自动恢复 |
| 自动偷取需人工审核 | `true` | 关掉就直接入库，不经审核区 |
| 表情收录模式（QQ_Official） | `cdn_only` | QQ 官方机器人平台的图片没有 OneBot 的表情标记：`all_images` 全收 / `cdn_only` 只收带表情 CDN 特征的 / `gif_only` 只收 GIF |
| LLM 偷图参数采纳策略 | `merge` | 详见 [LLM 工具与元数据回填](llm-tools.md#让-llm-自己填元数据) |

## 发图

| 配置项 | 默认 | 说明 |
|:---|:---|:---|
| 自动随聊发送表情包 | `true` | 总开关 |
| 启用发送意图判断 | `true` | 先判断这句话适不适合配表情包，明显不适合就跳过，能显著减少答非所问的乱发 |
| 新消息取消待发送表情 | `true` | 同一会话来了新消息，取消上一轮还在延迟等待中的表情 |
| 表情包发送概率 | `0.2` | 0.0 ~ 1.0 |
| 以 GIF 格式发送 | `false` | 更像真表情包，代价是发图时要把动图重新编码一遍。转换最多保留 30 帧并按总像素封顶（画面特别大的动图会自动少留几帧），512 见方的动图峰值内存约 15MB；内存紧张的机器建议关着 |
| 固定延迟（秒） | `5.0` | 避免和消息分段插件抢顺序，设 0 立即发 |
| 使用随机延迟 | `false` | 在固定延迟和最大随机延迟之间随机取值，更像真人 |
| 每字追加延迟（秒） | `0.3` | 按 Bot 这条回复的字数追加等待，模拟「先看完文字再发表情」 |
| 智能表情包选择 | `true` | 综合评分选图；关掉就是纯随机 |
| 自动表情的投递方式 | `separate` | `separate` 单独发一条 / `attach` 并进本条回复的消息链，见[和分段回复插件配合](platforms.md#和分段回复插件配合) |
| attach 模式选图超时（秒） | `10.0` | 只在 `attach` 模式生效；超时就回退成独立消息异步补发，不会卡住回复 |
| 为分段回复插件生成兼容路径 | `false` | 只在 `attach` 模式生效，见[那个「兼容路径」开关是干什么的](platforms.md#那个兼容路径开关是干什么的) |

## 情绪识别

| 配置项 | 默认 | 说明 |
|:---|:---|:---|
| 智能提取检索词 | `true` | `true` = LLM 模式（推荐）：轻量模型从 Bot 回复里提取检索词和情绪先验；`false` = 被动检索模式：直接用回复原文检索，不多花一次调用 |
| 情绪分析专用模型 | `""` | 留空用当前会话默认模型 |
| 情绪分析提示词 | 内置 | 留空使用内置模板 |

两种模式**都不会修改 LLM 原本的回复内容**，区别只在多不多一次轻量模型调用。

## 模型与检索

| 配置项 | 默认 | 说明 |
|:---|:---|:---|
| 视觉模型 | `""` | 留空自动使用 AstrBot 全局图片描述模型 |
| 启用嵌入向量检索 | `true` | 用向量库做语义匹配；关掉或不可用时降级 BM25 关键词检索 |
| 嵌入模型 ID | `""` | 留空自动用第一个 Embedding Provider |
| 文字距离融合预设 | `balanced` | 均衡 / 关键词优先 / 语义优先 / 严格匹配，四个预设代替手调五个小权重 |

## 批量识别

| 配置项 | 默认 | 范围 | 说明 |
|:---|:---|:---|:---|
| 批量识别并发数 | `2` | 1 ~ 16 | 同时送进视觉模型的图片数 |
| 批量识别每分钟请求上限 | `20` | 0 ~ 600 | 0 = 不限速。不清楚上游额度时按官方文档的 RPM 打七折填 |
| 批量识别重试次数 | `3` | 0 ~ 8 | 遇到限流 / 临时错误的重试上限 |
| 批量识别重试退避基数 | `2.0` | 1.0 ~ 10.0 | 每次重试等待时间的倍数 |

## 外部表情包源

| 配置项 | 默认 | 说明 |
|:---|:---|:---|
| 启用外部表情包源 | `true` | 总开关。关掉后相关接口一律拒绝，已导入的表情不受影响 |
| 允许明文 HTTP 源 | `false` | 默认只允许 `https://` 和本地文件，只在导入自建局域网服务时才需要打开 |
| 导入的图默认进待审核池 | `false` | 每次导入也能单独勾；开了「内容审核」时强制进待审核 |

另外五个上限项（单源张数 / 单图字节 / 压缩包体积 / 解压后总量 / 单图像素）的默认值和作用见[外部表情包源](external-sources.md#相关配置)。

## 存储与群聊过滤

| 配置项 | 默认 | 说明 |
|:---|:---|:---|
| 最大表情包数量 | `2000` | 表情库上限，填 `0` = 不限制。超出上限时会**永久删除**最旧的（收藏除外）。在配置页最顶部的「容量与安全」分组里，详见[表情库容量上限](#表情库容量上限) |
| 容量超限自动清理 | `false` | 关：超出上限只在日志里告警，一张都不删；开：后台每小时自动删最旧的 |
| 存储清理策略 | `balanced` | `conservative` 只清失效索引和临时文件 / `balanced` 再清孤立文件和缩略图 / `aggressive` 连 `raw` 原图备份一起清（最省空间，但无法回溯原图） |
| 发 / 收表情白名单、黑名单 | `[]` | 填 `group:群号` 或 `user:QQ号`，两者可同时生效 |
| 名单优先级 | `whitelist_first` | 白黑名单冲突时谁说话算数 |
| VLM 分类提示词 / 带审核版 | 内置 | 留空使用内置 `prompts.json` 模板 |

## 表情库容量上限

这是插件里唯一一个会**主动删你数据**的机制，单独讲清楚：

- **在哪里改**：AstrBot 插件配置页**最上面**那个分组「=== 容量与安全（重要）===」，第一项就是「最大表情包数量」。
- 「最大表情包数量」是硬上限。超出时从最旧的开始删，**图片文件一起删，删掉找不回来**（标记为收藏的不参与）。
- 默认 `2000`，够绝大多数人用。填 `0` 表示不限制，只受磁盘大小约束。
- 默认**不会自动删**：超出上限时只在日志里写一条告警（搜关键字「容量控制」能找到），告诉你现在多少张、超了几张。要清理请手动 `/mp capacity`；想让它每小时自动清，打开「容量超限自动清理」。
- 插件启动时也会检查一次，超了就直接在日志里说清楚（只告警，不删）。
- `/mp status` 只读数字不删东西，`/mp capacity` 才会真的删。

> ⚠️ **升级不会改写你已经保存过的配置。** AstrBot 只给缺失的配置项填默认值，所以你配置文件里存过的值不会被新的默认值覆盖。
>
> 早期版本这一项的默认上限很低（只有 100 张），而且后台巡检会自动删掉超出的部分。如果你是一路升级上来的，请去配置页顶部亲眼确认一次现在这个数字是多少——尤其是刚从旧插件迁移进来几百张图的时候。
