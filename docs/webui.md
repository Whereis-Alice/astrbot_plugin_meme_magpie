# WebUI 管理面板

> [← 返回 README](../README.md) · [文档目录](README.md) · [English](en/webui.md)

插件详情页点「表情神偷管理面板」进入，分两个区：

- **审核区**：自动收来的图先到这里，可以逐张或批量通过 / 删除，通过前能直接改分类、标签、描述、角色、作品。
- **图库**：按分类 / 作品 / 关键词筛选，四种排序（最常发送 / 最近发送 / 最新入库 / 最旧入库，全走 SQL），支持批量改分类、批量删除、批量设作用域、批量设角色 / 作品、批量修复来源作用域。

另外有：单张上传（可选 AI 自动识别）、批量导入、批量重新识别、识别失败检测、外部表情包源导入、重复图清理、存储维护（扫描并清理失效索引 / 孤立文件 / 缩略图缓存 / 临时文件）、分类管理。

界面有三套主题（自动 / 终端风 / 像素风）和三种语言，选择会记住。

快速切换分类、角色或搜索条件时，只显示最后一次请求的结果。分类 key 必须是安全的
单个目录名；已有合法中文分类和大小写保持不变，不自动改名或搬迁。路径分隔符、
系统保留名称和链接目录会被拒绝；分类更新会在保存前校验整批数据。

> **注意**：WebUI 里删除一个分类会同时删掉该分类下所有图片文件，操作前想清楚。

## 跨页全选、每页条数与清空图库

图库和审核区都支持**跨页选择**：进入批量模式后翻页不会丢掉已勾选的图片，底部批量栏会一直显示「已选 N 张」和「清空选择」。

- **全选本页**：选中或取消当前页，可以逐页累加；
- **全选全部 N 张 / N 条**：按当前筛选条件（关键词、分类、角色、收藏等）一次选中全部结果，再统一执行批量操作。它是一次性快照——点完之后即使改了筛选条件，已选范围也不会偷偷变大或缩小；
- **每页条数**：翻页栏右侧可选「自动 / 60 / 120 / 240」，选择会被记住；自动档按窗口大小铺满屏幕。图库和审核区共用同一个档位。

图库工具栏的「清空表情库」是一次性删掉整个图库（包括磁盘上的图片文件和缩略图缓存）的独立危险操作，不经过选择器。需要连续两次确认，第二次要手动输入 `DELETE`。它只清正式图库——待审核池、黑名单、外部源记录都不受影响；如果有文件删不掉，对应索引会保留，之后可以用「存储清理」重试。

## 备份导出与恢复

图库工具栏的「导出」把表情库打包成一个 `magpie-backup` 压缩包，用来定期备份或整库搬家：

- **范围**：全部图库，或当前筛选结果（搜索词 / 分类 / 角色 / 收藏）；
- **可选内容**：待审核池、黑名单，各自独立勾选，默认不带；
- **打包内容**：图片按分类分目录存放，另带完整元数据——描述、标签、场景、情绪、图上文字、角色、作品、收藏、使用次数、最近使用时间、入库与审核时间、感知哈希、可见范围与来源、保留级别；
- **下载**：后台打包并显示进度，完成后点「下载备份包」；文件在数据目录 `exports/` 下保留 2 小时，之后自动清理。

恢复走同一套通道：**外部源 → 上传压缩包**。插件识别出 `magpie-backup` 包后会给出三个开关：

- **只补空字段**：图片已存在时只填缺失的描述 / 标签等，已有内容绝不覆盖（默认关，纯增加）；
- **恢复待审核池**：把备份里的待审核条目放回池子；超过容量上限的部分会跳过并在进度里说明；
- **恢复黑名单**：把备份里的黑名单哈希写回。

备份里的新分类会自动创建、角色会自动注册，跨机器恢复不用手工补配置；相同图片按内容哈希去重，同一个包导两次不会产生重复。包内还带一份兼容子集（`semantic_metadata.json`），旧版本插件或其它工具也能读到基础描述与标签。

## 批量导入与批量重新识别

两个功能都在 WebUI 图库页，都受同一套限流器管理。

### 批量导入

一次上传几十上百张图，两种模式互斥：

- **指定分类**：直接存进你选的分类，不调用视觉模型，速度最快；
- **自动识别**：不选分类，由 VLM 逐张识别分类和标签。

导入前还可以统一填「角色」和「作品」，省得一张张改。

### 批量重新识别

给已经在库里的老图重跑视觉识别，适合两种场景：早期入库的图没标签、或者换了更好的视觉模型想重新标一遍。

- **范围**：勾选的图片 / 缺标签或缺描述的图片 / 只补没有描述的 / 全部图片
- **覆盖已有内容**：默认关闭，只往空字段里填，不动你手工写过的描述和标签
- **自动改分类**：默认关闭，只给出建议；开启后识别出的分类会直接应用，分类变化时会移动文件并更新索引
- **数量上限**：可以限制这一批最多处理多少张，先小范围试水

自动改分类是独立选项，不受「覆盖已有内容」影响：你可以保留手工描述，同时让识别失败的老图归到正确分类。批量写入前每张图都会按 hash 重新定位，文件移动和索引更新会串行处理，避免并发任务抢同一个目标路径；语义字段和分类会在同一次数据库事务里迁移。

更改视觉模型后，实际请求和识别缓存签名同步使用新模型；留空时实时读取框架默认视觉模型。
空 JSON、缺少必要分类字段或无效文本会在现有预算内重试，失败后明确报错，不再补成成功分类。
合法审核拒绝及完整旧管道格式仍然支持。

**审核区也能重新识别**：待审核池的图同样支持批量或单张重跑，范围一样是「勾选的 / 缺标签的 / 全部」。待审核记录的分类只是一个数据库字段，改它不需要移动文件，所以会按原有规则修正；正式库的分类对应真实目录，是否自动修正由上面的开关决定。

### 挑出识别失败的图

识别偶尔会失败——超时、被上游限流、模型返回空内容，都会留下一条「有图但没描述」的记录。描述是搜索的主要依据，空着这张图基本就搜不出来了。

图库和审核区的工具栏各有一个「识别失败」按钮，点开会列出所有描述为空、也就是列表里显示「暂无描述」的条目。每一条有三种处理方式：

- 自己写一句描述，点「仅保存」；
- 点「识别这张」只重跑这一张——**识别结果先填进输入框**，你确认无误再保存，不会背着你写库；
- 或者一键把这一批交给「批量重新识别」，几百张一次跑完。

待审核池条目特别多时只会检查最新的一批，弹窗里会写清本次检查了多少条，处理完再打开会接着往下检查。

### 怎么设并发和速率才不会被 429

限流器做了三件事：**并发上限**（同时在飞的请求数）、**RPM 令牌桶**（平均每分钟请求数）、**退避重试**（遇到 429 / 5xx / 超时自动等待重试，并把整条队列一起推后，避免几个 worker 前后脚接着撞墙）。

弹窗里的「并发」和「速率」是**这一次任务的临时值**，改了不影响插件配置；插件配置里的值是每次打开弹窗的默认值。

按上游额度对着填就行：

| 你的情况 | 并发 | 每分钟上限（RPM） |
|:---|:---:|:---:|
| 免费 / 试用额度，只知道很容易 429 | 1 | 6 ~ 10 |
| 常见付费 API（OpenAI、通义、智谱等入门档） | 2 ~ 3 | 20 ~ 60 |
| 高配额或自建推理服务 | 4 ~ 8 | 120 ~ 300 |
| 完全不想限速（本地模型） | 8 ~ 16 | 0（0 = 不限速，只受并发约束） |

不确定的话就用默认的「并发 2 + RPM 20」，几百张图大约一小时内跑完，基本不会触发限流。任务里如果被限流了，进度条上的「限流次数」和「重试次数」会实时涨，看到它涨就该往下调。

其余两项在插件配置里（`batch_analyze_max_retries` 重试次数，默认 3；`batch_analyze_retry_backoff` 退避基数，默认 2.0，即 1s → 2s → 4s 递增，带随机抖动）。上游返回了 `Retry-After` 头时会优先听它的。额度耗尽、Key 无效、鉴权失败这类**不可能重试成功**的错误会直接失败，不浪费额度。

### 进度显示

任务跑起来之后，进度面板会显示：

- 进度条 + 「已处理 / 总数」，暂停时进度条变色
- 当前正在处理的文件名和阶段（识别中 / 入库中）
- 成功 / 失败 / 已识别 / 限流次数 / 重试次数
- 预计剩余时间（按实际速率动态估算）
- 失败明细：哪张图失败了、失败原因
- 重新识别任务还会额外给出「改动了多少字段」「建议改分类的图片列表」和「已自动改分类的图片列表」

任务可以随时**暂停 / 继续 / 取消**，暂停是真的把 worker 停住，不是只停 UI。关掉浏览器标签页任务照样在后台跑，重新打开面板会自动接回进度。

## 外部表情包源

图库页还能整份导入别人做好的表情包——本地 `.zip` / `.meme-pack`、GitHub 仓库，或者一个返回清单 JSON 的 HTTPS 地址。先预检看清有多少张、分了哪些类，确认后才写库；导完的源会被记下来，之后能一键同步增量。

这块规则和安全限制比较多，单独写在[外部表情包源](external-sources.md)。
