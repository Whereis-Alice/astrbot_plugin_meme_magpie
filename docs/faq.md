# 常见问题

> [← 返回 README](../README.md) · [文档目录](README.md) · [English](en/faq.md)

**装了这个插件，原来的 astrbot_plugin_stealer 要卸载吗？**
不必须。两个插件的数据目录、命令前缀、WebUI 路由都不一样，可以共存。但**收图和发图功能会同时触发**，两个插件都开着会重复收图、重复发图。建议迁移完数据后把旧插件的收 / 发开关关掉，或直接卸载。

**迁移会不会弄坏旧插件的数据？**
`apply` 只读旧目录、只往新目录写，旧数据一个字节都不动，随时可以回退。只有 `move` 会移动文件，那才是不可逆的。

**为什么图片收进来了但没标签？**
基本都是视觉模型没配好或调用失败。看一眼 AstrBot 日志里有没有报错，确认「视觉模型」配置项或全局图片描述模型可用。已经入库的无标签图可以用 WebUI 的「批量重新识别」补上。

**批量识别一直 429 怎么办？**
把并发降到 1、RPM 降到 6~10 再试。如果还是 429，说明上游额度已经很紧，只能分批跑——用「数量上限」每次只处理几十张。

**服务器内存很小（1GB 甚至 512MB），批量识别几百张会不会撑爆？**
不会，但并发别开高。识别一张图的峰值内存已经和图片规模脱钩：512 见方 60 帧的动图约 17MB，1920×480 的 120 帧动图约 22MB，4000×4000 的静态图约 45MB。批量识别的峰值约等于「单张峰值 × 并发数」，所以小内存机器把「批量识别并发数」留在默认的 2 或调到 1 就行，跑几百张也只是慢一点，不会把内存吃满。另外「以 GIF 格式发送」会在发图时多一次编码，内存紧张时建议关着。

**表情包发得太频繁 / 太少？**
调「表情包发送概率」。发得答非所问就确认「启用发送意图判断」是开着的。

**必须配嵌入模型吗？**
不必须。没有嵌入模型会自动用 BM25 关键词检索，只是语义相近但用词不同的情况会差一些。

**改了描述，搜出来还是旧的内容？**
正常情况下不会——改描述会即时更新语义向量，重启也会按文本指纹补差。如果确实撞上了（旧数据里残留的错位向量），跑一次 `/mp rebuild_vectors` 清空重建即可。

**表情包数量上限是多少？会自动删我的图吗？**
默认 `2000` 张，填 `0` 就是不限制；配置项在插件配置页最顶部的「容量与安全」分组里。默认情况下超出上限**只告警不删**，要删得你自己跑 `/mp capacity`，或者打开「容量超限自动清理」。

**表情包无声无息少了几十张？**
先去日志里搜「容量控制」，再去插件配置页最顶部的「容量与安全」分组看一眼「最大表情包数量」现在是多少。早期版本的默认上限只有 100 张，后台每小时巡检一次、超出就把最旧的连文件一起删，日志里只有一行 INFO 很难注意到——从旧插件迁移进来几百张的人最容易踩。现在默认 2000 张并且默认只告警不删，**但升级不会改写你已经保存过的配置**，所以这个数字还得你自己确认一次。详见[表情库容量上限](configuration.md#表情库容量上限)。

**这插件会不会把别人的隐私截图收走？**
会——它不认识什么是隐私。所以默认开启了人工审核（自动收来的图先进审核区），并提供 `local` 作用域（只允许在来源群发送）和黑名单。建议保持审核开启，并用「偷表情黑名单」排除敏感群。

**用 LLBot / NapCat / SnowLuma，商城表情收不到？**
先确认 OneBot 的 `messageFormat` 是 `array` 而不是 `string`，插件要读原始消息段才能拿到商城表情。三家协议端本身的差异插件已经处理，细节见[平台与协议端支持](platforms.md#平台与协议端支持)。

**装了分段回复插件，表情包排版很怪？**
把「自动表情的投递方式」改成 `attach`，必要时再打开「为分段回复插件生成兼容路径」。见[和分段回复插件配合](platforms.md#和分段回复插件配合)。
