# 外部表情包源

> [← 返回 README](../README.md) · [文档目录](README.md) · [English](en/external-sources.md)

除了自己在群里一张张偷，你也可以把别人做好的整份表情包直接导进来。入口在 WebUI 图库页的「外部表情包源」。

它是**只读**的：源里的文件一个字节都不会被改动，图片是复制一份托管副本进本插件的数据目录。整个过程不执行源里的任何代码，也不会 `git clone`。

## 三类源

### 本地表情包压缩包

浏览器里选一个 `.zip` 或 `.meme-pack` 上传，上传完立刻预检。

推荐的目录结构是 AstrBot Meme Pack v2 导出格式：

```text
my-pack/
├─ manifest.json              # 包的 id / 名称 / 分类表（推荐）
├─ meme_pack_export.json      # v2 导出描述文件（可选）
├─ memes/<分类名>/*           # 图片，必需
├─ semantic_metadata.json     # 每张图的描述 / 标签 / 图上文字（可选）
└─ previews/                  # 预览图，导入时跳过
```

元数据文件不是必需的。`manifest.json`、`memes_data.json`、`semantic_index.json`、`semantic_metadata.json`、`meme_pack_export.json` 认哪个都行；一个都没有也能导——分类名从 `memes/` 下的第一层目录（或图片所在目录）推断，描述和标签留空，事后用 WebUI 的「识别失败」批量补。

认得的图片格式：`png` / `jpg` / `jpeg` / `gif` / `webp` / `bmp`。`previews/`、`thumbnails/`、`thumbs/` 这类预览目录会被跳过。

如果同一个 AstrBot 里装了 [astrbot_plugin_meme_manager](https://github.com/anka-afk/astrbot_plugin_meme_manager)，它 `packs/<pack-id>/` 下的包会**自动出现在源列表里**，标着「自动发现」，不用手动上传。

读取逻辑跟随公开的 [AstrBot Meme Pack 协议](https://github.com/anka-afk/astrbot-meme-pack-index/blob/main/ASTRBOT_MEME_PACK_PROTOCOL_ZH.md)，不认识的字段会安全忽略。

### GitHub 仓库

填 `owner/repo`，或者直接贴链接：

```text
owner/repo
https://github.com/owner/repo
https://github.com/owner/repo/tree/v1.1.0
https://github.com/owner/repo/tree/main/packs/happy
owner/repo?ref=feature/new-pack&subpath=packs/happy
```

`/tree/<分支或 tag>/<子目录>` 用来选分支和仓库里的某个子目录；分支名里带 `/` 时用 `?ref=&subpath=` 的写法。不填分支就走 GitHub API 解析默认分支。

仓库是以 ZIP 存档的形式下载到 `external_sources/github_cache/`，然后交给上面那套压缩包读取器，所以仓库的布局要求和本地包完全一样（`manifest.json` + `memes/` 在根目录或所选子目录下）。

### HTTP 目录

一个返回表情包清单 JSON 的 HTTPS 地址。顶层可以直接是数组，也可以是对象——条目数组叫 `items`、`memes`、`data` 或 `results` 都认：

```json
{
  "id": "community-reactions",
  "name": "社区表情合集",
  "version": "2026.09",
  "license": "CC-BY-4.0",
  "attribution": "Example Community",
  "items": [
    {
      "id": "happy-001",
      "url": "https://cdn.example.org/memes/happy-001.webp",
      "category": "开心",
      "description": "笑得很开心的反应图",
      "visible_text": "好耶",
      "tags": ["庆祝", "赞同"],
      "scenes": ["回应好消息"],
      "emotions": ["开心", "兴奋"],
      "character": "露西亚",
      "work": "某作品",
      "license": "CC-BY-4.0",
      "attribution": "画师名"
    }
  ],
  "next_cursor": "page-2"
}
```

常见字段都接受别名：

| 实际含义 | 认的字段名 |
|:---|:---|
| 条目 ID | `id` / `external_id` / `key` |
| 图片地址 | `url` / `image_url` / `source_url` / `src` |
| 分类 | `category` / `emotion` |
| 描述 | `description` / `desc` |
| 图上文字 | `visible_text` / `overlay_text` |
| 使用场景 | `scenes` / `scene` |
| 角色 | `character` / `role` |
| 作品 | `work` / `series` / `source_work` |
| 作者署名 | `attribution` / `author` |

顶层的 `license` / `attribution` 会作为默认值填给没写的条目。图片地址可以是绝对地址，也可以是相对于清单地址的相对路径。翻页返回 `next_cursor` 或 `next`，插件会带 `?cursor=<值>` 再请求同一个地址；游标重复出现就安全停止，最多翻 100 页。

需要鉴权的接口可以在登记源时附带 `Accept`、`Authorization`、`User-Agent`、`X-API-Key` 四个请求头。**头的值会存进插件数据库**（否则下次同步无法鉴权），但源列表接口一律脱敏返回，来源信息里也不会写入凭据类字段——请照看好 AstrBot 的数据目录。

## 导入流程

1. **预检**：只读清单，不写任何数据。告诉你有多少张、多大、分了哪些类、作者声明是什么，并抽几条内容给你看。如果导完会超过「最大表情包数量」，这一步就会警告。
2. **分类对应**：左边是包里的分类名，右边选它落到你本地哪一类。留「自动」就按名字和近义词猜，猜不中落到兜底分类。
3. **可选项**：先进待审核池、可见范围（含 `group:群号` 这类限定会话）、整批标成同一个角色。
4. **逐张写库**：按字节上限读取 → Pillow 解码校验格式 → 像素上限 → SHA-256 去重 → 原子复制进目标分类或待审核池。
5. **结果**：已入库 / 进待审核 / 重复跳过 / 失败四个计数。

导入会记下描述、图上文字、标签、场景、情绪、原始文件名、尺寸、格式、许可证、署名和来源地址。已经在正式库或待审核池里存在的图（按哈希判断）不会复制第二份，只是把它关联到这个源上——**重复算「重复」，不算失败**。

### 三件和你预期可能不一样的事

**导入不调用视觉模型。** 几百张图逐张跑 VLM 又慢又烧钱，而且好包本来就自带描述。插件直接沿用包里的描述和标签；包里没写的就是空的。补的办法是导完之后用图库工具栏的「识别失败」检测出没描述的条目，一次性交给批量重新识别，那边有并发和速率限制，不会打爆上游。

**角色名不会无条件写库。** 包里写的角色名，只有恰好能对上你**已经登记过**的角色才会写进数据库；对不上的原文留在来源信息里，不会污染你的角色库。想给整批指定一个新角色，就勾上「整批标成同一个角色」并填新名字，插件会顺便登记它——不勾选而填了未知角色，整批会被拒绝，不会悄悄创建。

**外部源的图不参与容量淘汰。** 它们的 `retention_class` 是 `external`，「最大表情包数量」清理时会跳过。这意味着导入一大份包不会把你自己偷的表情挤掉，但反过来——如果外部源的图占满了硬盘，容量上限也管不了它们，需要你手动删。收藏的图仍然计入容量，只是清理时排在最后。

另外，插件配置里开了「内容过滤」时，外部源导入**一律**先进待审核池，弹窗里的开关会被锁死。待审核池满了会直接拒绝这次导入，不会边导边丢。

## 已登记的源与增量同步

导入成功的源会记进「已登记的源」列表，之后：

- **同步**：重新读一遍源，只导新增的条目。上次见过、这次清单里没有的条目**不会被删**，只是在来源信息里标成 `stale`（源方删了图，但你的副本还在）。同步失败不会误标 stale。
- **移除**：只删登记记录和来源信息，**已经导进来的表情包一张都不会删**。

同一时间只允许一个导入 / 同步任务，暂停中的任务仍然占着这个名额。任务可以暂停、恢复、取消；取消后已入库的部分保留。任务面板显示阶段（排队 → 读取清单 → 入库 → 收尾）、进度、四个计数和预计剩余时间。单个任务累计 20 条错误就会停下，避免源整体坏掉时刷几百条日志。

浏览器上传的压缩包暂存在 `external_sources/uploads/`，24 小时后自动清理；正被某个任务引用的不会被清掉。

## 安全边界

- 只允许 `https://`，除非你显式打开「允许明文 HTTP 源」。
- 拒绝 loopback / 私网 / 链路本地 / 组播 / 保留地址，字面量和 DNS 解析结果都查，重定向也查。URL 里带 `user:pass@` 直接拒。
- 跨域重定向会丢掉 `Authorization` 和 `X-API-Key`，避免凭据被转发给第三方。
- 压缩包成员的绝对路径、`..` 穿越、软链接、成员数超限、压缩 / 解压体积超限、单文件超大、空包，全部拒绝。
- 清单体积、单张图体积、条目总数、像素数、翻页数、重定向次数、后台任务数都有上限。
- 通过 Web API 传的本地路径必须在 AstrBot 的插件数据目录之内，不能变成任意文件读取。
- 返回给前端的接口地址和来源信息会脱敏。

## 相关配置

配置页「外部表情包源」分组：

| 配置项 | 默认 | 说明 |
|:---|:---|:---|
| 启用外部表情包源 | `true` | 总开关，关掉后所有相关接口一律拒绝，已导入的表情不受影响 |
| 允许明文 HTTP 源 | `false` | 只在导入自建局域网服务时才需要打开 |
| 导入的图默认进待审核池 | `false` | 每次导入也能单独勾 |
| 单个源最多导入张数 | `2000` | 超出部分截断，预检里会提示 |
| 单张图字节上限 | 32 MiB | 超过的图跳过并记入失败 |
| 压缩包体积上限 | 1 GiB | 压缩包本身的大小 |
| 解压后总字节上限 | 4 GiB | 挡「解压炸弹」 |
| 单张图像素上限 | 4000 万（约 6300×6300） | 挡解码时吃光内存的巨图 |

## 疑难

**预检报错但看不懂。** 底层的源读取器为了方便对外贴 issue，错误文案是英文的，前端会给它加一个中文前缀（比如「预检没跑完，可能是网络或源不可达：...」）。前缀是插件给的，后半段原文来自读取器。

**GitHub 源下载很慢或超时。** 走的是 GitHub 的存档下载地址，大仓库会比较久。如果你的机器需要代理，得让 AstrBot 进程本身能走代理（环境变量 `HTTPS_PROXY`），插件不单独配代理。

**同一个源导两次会重复吗？** 不会。去重按图片内容的 SHA-256 走，同一张图无论从哪个源来都只存一份副本，多出来的只是「这张图也属于那个源」的关联记录。
