## 这是什么

喜鹊自古是出名的贼鸟，看到亮闪闪的东西就往窝里叼。这个插件干的是同一件事——群里刷过的表情包，它顺手偷进图库，用视觉模型看懂「这张图在表达什么」，分类、打标签、抄下图上的字，然后在 Bot 回复时挑一张情绪对得上的发出去。

三件事各自独立开关，互不影响：

- **收**：监听聊天里的图片，按概率或冷却收进「待审核池」，你在 WebUI 点通过才正式入库。
- **认**：视觉模型（VLM）识别分类、标签、使用场景、图上文字、角色和作品。
- **发**：Bot 回复后按概率决定要不要配一张表情包；选哪张走语义检索 + 情绪匹配。

不想让它继续收了就 `/mp off`，已经进库的表情包照样能发。

### 关于名字

对外的名字是 **meme神偷**（英文 Meme Thief），指令组是 `mp`——meme + pilfer，两个字母好敲。

1.0 时期叫「表情包喜鹊」，所以旧的 `magpie` 和中文 `神偷` 都保留成别名，三种写法完全等价：

```
/mp status
/magpie status
/神偷 status
```

仓库名和 Python 包名仍然是 `astrbot_plugin_meme_magpie`，这个是**故意不改**的：AstrBot 拿 `metadata.yaml` 里的 `name` 当插件目录名，同时也当数据目录 `data/plugin_data/<name>`。改掉它等于让所有老用户的表情包和数据库「凭空失踪」，所以这一层保持原样。

### 和 astrbot_plugin_stealer 的关系

本插件基于 [nagatoquin33/astrbot_plugin_stealer](https://github.com/nagatoquin33/astrbot_plugin_stealer) 二次开发（AGPL-3.0），感谢原作者把这套玩法做出来。

它是一个**完全独立的插件**：包名、命令前缀、数据目录、WebUI 路由、LLM 工具名都换过了，可以和原插件装在同一个 AstrBot 里共存，不会互相覆盖数据。如果你原来在用 stealer，一条 `/mp migrate apply` 就能把表情包和数据库搬过来，旧数据默认原样保留。

相比原插件，这一版主要多了这些东西：

| 改动 | 说明 |
|:---|:---|
| **数据迁移指令** | `/mp migrate` 一条指令搬走旧插件的图片、数据库、分类、角色库、黑名单和配置 |
| **LLM 直接传参入库** | LLM 主动收图时可以顺手写清「这是哪个作品的哪个角色、在做什么」，不再只靠视觉模型猜 |
| **批量识别限流** | 批量导入 / 批量重新识别可设并发数与每分钟请求上限，几百张图也不会打爆上游触发 429 |
| **作品维度** | 新增「作品名」字段，从入库、检索一路贯通到 WebUI 筛选 |
| **批量重新识别** | 对已入库但缺标签 / 缺描述的老图重跑视觉识别，可选只补空、不覆盖已有内容 |
| **若干上游 Bug 修复** | 见下文[修了哪些问题](#修了哪些问题) |

## 核心功能

| 功能 | 说明 |
|:---|:---|
| **自动收集** | 监听聊天图片，概率 / 冷却两种模式；QQ 官方机器人平台有专门的表情识别策略 |
| **待审核池** | 自动收来的图先进审核区，人工点通过才入库，避免图库被随手截图污染 |
| **视觉识别** | VLM 输出结构化 JSON：分类、标签（0~3 个）、使用场景（1~2 个）、图上文字、情绪 |
| **语义检索** | 图上文字 + 使用场景 + 文本嵌入向量匹配；分类只加分不硬过滤；嵌入不可用时自动降级 BM25 |
| **情绪匹配** | 从 Bot 回复中提取检索词和情绪先验，挑一张对得上的，不改动 LLM 原本的回复内容 |
| **LLM 主动用图** | 对话中 LLM 可以自己检索、发送、收录表情包 |
| **角色与作品库** | 手工归档「这是谁 / 出自哪部作品」，和情绪分类相互独立 |
| **WebUI 管理面板** | 审核区 + 图库双区：浏览、编辑、排序、批量操作、批量导入、批量重新识别、存储清理 |
| **群聊过滤** | 收和发各有独立黑白名单，支持 `group:群号` 和 `user:QQ号` |
| **重复图清理** | 感知哈希（pHash）找出内容重复的图 |
| **多语言界面** | 中文 / English / Русский |

## 快速开始

### 1. 先配好视觉模型

插件靠 VLM 读懂图片，**没有视觉模型基本等于不能用**。两种配法任选其一：

- 在 AstrBot 后台配好「图片描述模型」，插件会自动拿来用；
- 或者在插件配置里单独指定「视觉模型」（`vision_provider_id`）。

嵌入模型（Embedding）是可选项：配了检索更准，没配会自动降级成 BM25 关键词检索，功能不受影响。

### 2. 安装

在 AstrBot 插件市场搜索 `astrbot_plugin_meme_magpie`，或者在插件管理页面用仓库地址安装：

```
https://github.com/Whereis-Alice/astrbot_plugin_meme_magpie
```

### 3. 三条命令跑起来

```
/mp on        # 开始收表情包
/mp auto_on   # 开启聊天时自动发表情包
/mp status    # 看看现在收了多少
```

> **关于 `/` 这个前缀**：`/` 只是 AstrBot 的出厂默认唤醒前缀，你可以在 AstrBot 设置里把它改成 `!`、`#`、`.`，也可以整个清空（清空后直接发 `mp status`）。本文档一律按默认的 `/` 书写，请自行替换成你实际用的那个。私聊或者 @机器人 的场合本来就不需要前缀。
>
> 不确定自己的前缀是哪个？插件所有回复里的命令示例都会按**你实际生效的前缀**渲染，照抄回复里的写法就行；发一次 `mp help` 可以打印完整的子命令清单。

### 4. 打开管理面板

AstrBot 插件详情页 →「表情神偷管理面板」。不用额外开端口，不用另设密码。

## 从原插件迁移数据

`/mp migrate` 用来把 `astrbot_plugin_stealer` 的数据搬到本插件。整个过程是**幂等的**（重复执行不会重复导入）、**非破坏性的**（默认复制文件，旧插件数据原样保留），可以放心先试。

推荐三步走：

```
/mp migrate check     # 第一步：看看能不能找到旧插件的数据目录
/mp migrate           # 第二步：预演，只打印「如果执行会发生什么」，一个字节都不写
/mp migrate apply     # 第三步：真的搬（复制文件，旧数据保留）
```

磁盘紧张、不想留两份图片的话，用 `/mp migrate move` 代替 `apply`——它移动而不是复制文件，**执行后旧插件就不可用了**，请先用前两步确认无误。

自动找不到旧目录时，手动把路径给它：

```
/mp migrate apply D:/astrbot/data/plugin_data/astrbot_plugin_stealer
```

**会搬的东西**

- `categories/` 下所有分类图片、`pending/` 待审核图片、`raw/` 暂存图片
- 数据库里的表情包记录：分类、标签、场景、描述、情绪、使用次数、作用域、来源、入库方式等
- 待审核池记录、去重黑名单
- `categories.json` / `category_info.json` / `characters.json` / `character_info.json`
- 旧插件的配置项（只搬本插件也有的键，本插件新增的配置保持默认值）

**不会搬的东西**：缩略图缓存、临时文件、嵌入向量。迁移完跑一次 `/mp rebuild_index` 重建索引即可。

迁移结束会打印一份报告：搬了多少张图、跳过多少张（已存在 / 文件缺失 / 哈希重复）、失败多少张。文件名撞车时自动改名，绝不覆盖已有的图。

## LLM 主动用图

对话中 LLM 可以自己调三个工具，不需要你下指令：

| 工具 | 作用 |
|:---|:---|
| `magpie_search_meme` | 检索候选表情包，返回分类、作品、角色、场景、作用域、使用次数等参考信息 |
| `magpie_send_meme` | 从候选里挑一张发出去；发送失败会返回明确原因，方便 LLM 重选 |
| `magpie_steal_meme` | 把当前消息里的图片收进库；`image_ref` 留空则自动取第一张图 |

### 让 LLM 自己填元数据

视觉模型认不出「这是《孤独摇滚》里的后藤一里在抱头」这种二次元细节，是这类插件最常见的翻车点。所以 `magpie_steal_meme` 开放了参数，让**聊天中的 LLM 把它已经知道的信息直接写进库**：

| 参数 | 说明 |
|:---|:---|
| `work` | 作品名，比如「孤独摇滚」「原神」 |
| `character` | 角色名，比如「后藤一里」 |
| `action` | 图里在做什么动作，比如「抱头」「捂脸」 |
| `desc` | 一句话描述这张图 |
| `tags` | 关键词标签，逗号或顿号分隔 |
| `scenes` | 适合什么场景用，逗号或顿号分隔 |
| `emotions` | 情绪词，逗号或顿号分隔 |
| `overlay_text` | 图上写的字 |
| `category` | 指定分类（必须是已有分类名，非法值会被忽略并回退） |

参数全填、填一半、一个都不填都可以，缺的部分继续交给视觉模型补。用法举例——你在群里说：

> 把这张图偷了，这是孤独摇滚的波奇酱，在抱头尖叫

LLM 就会带着 `work="孤独摇滚"`、`character="后藤一里"`、`action="抱头尖叫"` 调用工具，入库质量比纯靠视觉模型高一个档次。

三种采纳策略由配置项**「LLM 偷图参数采纳策略」**（`llm_steal_param_mode`）决定：

| 取值 | 行为 | 适合 |
|:---|:---|:---|
| `merge`（默认） | LLM 给的字段优先，没给的用 VLM 分析结果补 | 绝大多数情况 |
| `llm_first` | LLM 给齐了关键字段就**跳过 VLM 调用**，省一次请求 | 想省 Token，且信任对话模型 |
| `vlm_only` | 忽略 LLM 传的参数，只用 VLM 分析 | 想完全交给视觉模型 |

无论哪种策略，**内容审核始终在最前面执行，LLM 无法绕过**。

## 批量导入与批量重新识别

两个功能都在 WebUI 图库页，都受同一套限流器管理。

### 批量导入

一次上传几十上百张图，两种模式互斥：

- **指定分类**：直接存进你选的分类，不调用视觉模型，速度最快；
- **自动识别**：不选分类，由 VLM 逐张识别分类和标签。

导入前还可以统一填「角色」和「作品」，省得一张张改。

### 批量重新识别

给已经在库里的老图重跑视觉识别，适合两种场景：早期入库的图没标签、或者换了更好的视觉模型想重新标一遍。

- **范围**：勾选的图片 / 缺标签或缺描述的图片 / 全部图片
- **覆盖已有内容**：默认关闭，只往空字段里填，不动你手工写过的描述和标签
- **数量上限**：可以限制这一批最多处理多少张，先小范围试水
- 出于安全考虑，重新识别**不会自动改分类**（改分类要移动文件，并发下风险高），只在结果里给出「建议分类」，你自己决定要不要改

### 怎么设并发和速率才不会被 429

限流器做了三件事：**并发上限**（同时在飞的请求数）、**RPM 令牌桶**（平均每分钟请求数）、**退避重试**（遇到 429 / 5xx / 超时自动等待重试，并把整条队列一起推后，避免几个 worker 前后脚接着撞墙）。

弹窗里的「并发」和「速率」是**这一次任务的临时值**，改了不影响插件配置；插件配置里的值是每次打开弹窗的默认值。

按上游额度对着填就行：

| 你的情况 | 并发 | 每分钟上限（RPM） |
|:---|:---:|:---:|
| 免费 / 试用额度，只知道很容易 429 | 1 | 6 ~ 10 |
| 常见付费 API（OpenAI、通义、智谱等入门档） | 2 ~ 3 | 20 ~ 60 |
| 高配额或自建推理服务 | 4 ~ 8 | 120 ~ 300 |
| 完全不想限速（本地模型） | 8 ~ 16 | 0（0 = 不限速，只受并发约束） |

不确定的话就用默认的「并发 2 + RPM 20」，几百张图大约一小时内跑完，基本不会触发限流。任务里如果被限流了，进度条上的「限流次数」和「重试次数」会实时涨，看到它涨就该往下调。

其余两项在插件配置里（`batch_analyze_max_retries` 重试次数，默认 3；`batch_analyze_retry_backoff` 退避基数，默认 2.0，即 1s → 2s → 4s 递增，带随机抖动）。上游返回了 `Retry-After` 头时会优先听它的。额度耗尽、Key 无效、鉴权失败这类**不可能重试成功**的错误会直接失败，不浪费额度。

### 进度显示

任务跑起来之后，进度面板会显示：

- 进度条 + 「已处理 / 总数」，暂停时进度条变色
- 当前正在处理的文件名和阶段（识别中 / 入库中）
- 成功 / 失败 / 已识别 / 限流次数 / 重试次数
- 预计剩余时间（按实际速率动态估算）
- 失败明细：哪张图失败了、失败原因
- 重新识别任务还会额外给出「改动了多少字段」和「建议改分类的图片列表」

任务可以随时**暂停 / 继续 / 取消**，暂停是真的把 worker 停住，不是只停 UI。关掉浏览器标签页任务照样在后台跑，重新打开面板会自动接回进度。

### 所有人可用

| 指令 | 说明 |
|:---|:---|
| `status` | 运行状态和表情包统计 |

| `emotion_stats` | 情绪分析统计和当前模式 |
| `help` / `帮助` | 按你当前的唤醒前缀打印完整子命令清单 |

### 仅管理员

| 指令 | 说明 |
|:---|:---|
| `on` / `off` | 开启 / 关闭表情包收集 |
| `auto_on` / `auto_off` | 开启 / 关闭自动发送 |

| `clear_emotion_cache` | 清空情绪分析缓存 |

## 配置说明

所有配置项都在 AstrBot 插件配置页里改，下面只列关键项。

### 收图

| 配置项 | 默认 | 说明 |
|:---|:---|:---|
| 开启表情包偷取功能 | `false` | 总开关 |
| 偷图模式 | `probability` | `probability` 按概率 / `cooldown` 按冷却时间 |
| 偷图概率 | `0.3` | 概率模式下每张图被收下的概率 |
| 偷图冷却时间（秒） | `30` | 冷却模式下两次收图的最小间隔 |
| 内容审核 | `false` | 开启后过滤不当图片，会多一次模型调用 |
| 审核异常时放行 | `false` | 审核调用本身失败时的兜底行为。默认拒绝（更安全），开启则放行 |
| 待审核池容量上限 | `200` | 待审核图片攒到上限就暂停收图，审核通过后自动恢复 |
| 自动偷取需人工审核 | `true` | 关掉就直接入库，不经审核区 |
| 表情收录模式（QQ_Official） | `cdn_only` | QQ 官方机器人平台的图片没有 OneBot 的表情标记：`all_images` 全收 / `cdn_only` 只收带表情 CDN 特征的 / `gif_only` 只收 GIF |
| LLM 偷图参数采纳策略 | `merge` | 见上文[让 LLM 自己填元数据](#让-llm-自己填元数据) |

### 发图

| 配置项 | 默认 | 说明 |
|:---|:---|:---|
| 自动随聊发送表情包 | `true` | 总开关 |
| 启用发送意图判断 | `true` | 先判断这句话适不适合配表情包，明显不适合就跳过，能显著减少答非所问的乱发 |
| 新消息取消待发送表情 | `true` | 同一会话来了新消息，取消上一轮还在延迟等待中的表情 |
| 表情包发送概率 | `0.2` | 0.0 ~ 1.0 |
| 以 GIF 格式发送 | `false` | 更像真表情包，但超大图转 GIF 会有内存尖峰，低内存机器别开 |
| 固定延迟（秒） | `5.0` | 避免和消息分段插件抢顺序，设 0 立即发 |
| 使用随机延迟 | `false` | 在固定延迟和最大随机延迟之间随机取值，更像真人 |
| 每字追加延迟（秒） | `0.3` | 按 Bot 这条回复的字数追加等待，模拟「先看完文字再发表情」 |
| 智能表情包选择 | `true` | 综合评分选图；关掉就是纯随机 |

### 情绪识别

| 配置项 | 默认 | 说明 |
|:---|:---|:---|
| 智能提取检索词 | `true` | `true` = LLM 模式（推荐）：轻量模型从 Bot 回复里提取检索词和情绪先验；`false` = 被动检索模式：直接用回复原文检索，不多花一次调用 |
| 情绪分析专用模型 | `""` | 留空用当前会话默认模型 |
| 情绪分析提示词 | 内置 | 留空使用内置模板 |

两种模式**都不会修改 LLM 原本的回复内容**，区别只在多不多一次轻量模型调用。

### 模型与检索

| 配置项 | 默认 | 说明 |
|:---|:---|:---|
| 视觉模型 | `""` | 留空自动使用 AstrBot 全局图片描述模型 |
| 启用嵌入向量检索 | `true` | 用向量库做语义匹配；关掉或不可用时降级 BM25 关键词检索 |
| 嵌入模型 ID | `""` | 留空自动用第一个 Embedding Provider |
| 文字距离融合预设 | `balanced` | 均衡 / 关键词优先 / 语义优先 / 严格匹配，四个预设代替手调五个小权重 |

### 批量识别

| 配置项 | 默认 | 范围 | 说明 |
|:---|:---|:---|:---|
| 批量识别并发数 | `2` | 1 ~ 16 | 同时送进视觉模型的图片数 |
| 批量识别每分钟请求上限 | `20` | 0 ~ 600 | 0 = 不限速。不清楚上游额度时按官方文档的 RPM 打七折填 |
| 批量识别重试次数 | `3` | 0 ~ 8 | 遇到限流 / 临时错误的重试上限 |
| 批量识别重试退避基数 | `2.0` | 1.0 ~ 10.0 | 每次重试等待时间的倍数 |

### 存储与群聊过滤

| 配置项 | 默认 | 说明 |
|:---|:---|:---|
| 最大表情包数量 | `100` | 超出后自动清理最旧的，想无限存就往大调 |
| 存储清理策略 | `balanced` | `conservative` 只清失效索引和临时文件 / `balanced` 再清孤立文件和缩略图 / `aggressive` 连 `raw` 原图备份一起清（最省空间，但无法回溯原图） |
| 发 / 收表情白名单、黑名单 | `[]` | 填 `group:群号` 或 `user:QQ号`，两者可同时生效 |
| 名单优先级 | `whitelist_first` | 白黑名单冲突时谁说话算数 |
| VLM 分类提示词 / 带审核版 | 内置 | 留空使用内置 `prompts.json` 模板 |

## WebUI 管理面板

插件详情页点「表情神偷管理面板」进入，分两个区：

- **审核区**：自动收来的图先到这里，可以逐张或批量通过 / 删除，通过前能直接改分类、标签、描述、角色、作品。
- **图库**：按分类 / 作品 / 关键词筛选，四种排序（最常发送 / 最近发送 / 最新入库 / 最旧入库，全走 SQL），支持批量改分类、批量删除、批量设作用域、批量设角色 / 作品、批量修复来源作用域。

另外有：单张上传（可选 AI 自动识别）、批量导入、批量重新识别、重复图清理、存储维护（扫描并清理失效索引 / 孤立文件 / 缩略图缓存 / 临时文件）、分类管理。

界面有三套主题（自动 / 终端风 / 像素风）和三种语言，选择会记住。

> **注意**：WebUI 里删除一个分类会同时删掉该分类下所有图片文件，操作前想清楚。

## 常见问题

**装了这个插件，原来的 astrbot_plugin_stealer 要卸载吗？**
不必须。两个插件的数据目录、命令前缀、WebUI 路由都不一样，可以共存。但**收图和发图功能会同时触发**，两个插件都开着会重复收图、重复发图。建议迁移完数据后把旧插件的收 / 发开关关掉，或直接卸载。

**迁移会不会弄坏旧插件的数据？**
`apply` 只读旧目录、只往新目录写，旧数据一个字节都不动，随时可以回退。只有 `move` 会移动文件，那才是不可逆的。

**为什么图片收进来了但没标签？**
基本都是视觉模型没配好或调用失败。看一眼 AstrBot 日志里有没有报错，确认「视觉模型」配置项或全局图片描述模型可用。已经入库的无标签图可以用 WebUI 的「批量重新识别」补上。

**批量识别一直 429 怎么办？**
把并发降到 1、RPM 降到 6~10 再试。如果还是 429，说明上游额度已经很紧，只能分批跑——用「数量上限」每次只处理几十张。

**表情包发得太频繁 / 太少？**
调「表情包发送概率」。发得答非所问就确认「启用发送意图判断」是开着的。

**必须配嵌入模型吗？**
不必须。没有嵌入模型会自动用 BM25 关键词检索，只是语义相近但用词不同的情况会差一些。

**存储上限 100 张是不是太少？**
默认值保守，按需往大调。注意超过上限会自动清掉最旧的图，调小之前先确认不会误删。

**这插件会不会把别人的隐私截图收走？**
会——它不认识什么是隐私。所以默认开启了人工审核（自动收来的图先进审核区），并提供 `local` 作用域（只允许在来源群发送）和黑名单。建议保持审核开启，并用「偷表情黑名单」排除敏感群。

## 修了哪些问题

相比上游 `astrbot_plugin_stealer`，这一版顺手修掉了这些：

- **标签统计命令会偿删暂存目录，清理命令反而从未生效**：上游的 `clean` 方法丢了定义行，代码全部掉进了上一个方法的函数体里。结果是 `clean` 执行时报 `AttributeError`，而本应只读的 `tag_stats` 每跑一次就会把 `raw` 暂存目录清空（里面可能还有正在排队等识别的图）。现在两个命令已拆开，并加了回归测试锁住。
- **LLM 收图的入库方式记错**：LLM 通过工具收的图，`add_method` 被记成 `auto`（自动偷取），导致统计口径和自动收图混在一起，现在正确记为 `llm`。
- **批量识别失败时留下脏数据**：视觉模型返回了非法分类时，上游只回退分类，却把同一次分析产出的标签和描述留在了库里。现在整份分析结果一起丢弃，避免「分类是兜底的、标签却是乱的」。
- **WebUI 搜索漏字段**：索引兜底分支只搜标签 / 描述 / 场景，搜不到图上文字、角色、作品、原始文件名。现在与 SQL 分支的字段范围对齐。
- **批量导入无限并发**：上游 README 自己写着「高并发警告，请分批次分析」。现在换成可配置并发 + RPM 令牌桶 + 退避重试，不需要人肉分批。
- **内容审核失败时静默放行**：审核模型超时或额度用尽时的行为不可控。现在默认「审核失败即拒收」，需要放行的人可以显式打开「审核异常时放行」。
- **清理了死代码**：删掉了不再被调用的 `steal_image_direct` 分支。

## 注意事项

- **必须配置视觉模型**，否则识别相关的功能全都不工作。
- WebUI 删除分类会连带删除该分类下的所有图片文件。
- 开启「以 GIF 格式发送」时，超大图强制转 GIF 会产生内存尖峰，低内存环境建议关闭。
